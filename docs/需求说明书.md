# 项目需求说明书

## 一、项目定位

本项目为《软件项目管理》课程第一次作业的门诊咨询系统**原型方案**，基于**模拟知识库**完成文本问答的需求设计与 UML 建模。

- 不接入真实医院信息系统；
- 不查询真实患者数据；
- 不提供诊疗建议；
- 所有数据均为课程演示用模拟数据。

## 二、业务背景

医院门诊导诊台长期承担科室位置、挂号流程、就诊材料、医保报销规则等重复性咨询。在课程设计场景下，我们用一套基于模拟知识库的智能问答原型，描述"患者输入问题 → 系统返回标准化流程指引"的业务流程，并讨论未命中问题的处理方式。

## 三、功能范围（本次作业仅包含以下四项）

1. **患者输入门诊流程咨询问题**：患者在对话界面输入文本问题，如"挂号要带什么""拍片后多久取报告"。
2. **系统从模拟知识库返回标准化流程指引**：系统在模拟知识库中匹配条目，返回预定义的流程说明文本。
3. **未命中处理**：当模拟知识库中没有对应条目时，系统不猜测答案，提示患者前往门诊导诊台或拨打咨询电话，并将该问题匿名记录，供后续知识库补充。
4. **管理员维护模拟知识库条目**：管理员可对模拟知识库中的问答条目进行新增、编辑、删除，不涉及任何真实患者数据。

## 四、明确排除范围（后续版本或本次作业不涉及）

以下内容在本次作业中**不做需求设计、不建模、不实现**：

- 用户注册与登录；
- 真实挂号、缴费、报告查询、医保结算；
- 多轮上下文对话；
- 转人工客服与在线坐席；
- 诊断、处方、用药建议；
- 真实患者身份识别与病历访问；
- 语音、视频等多媒体交互。

## 五、角色

| 角色 | 说明 |
|------|------|
| 患者（原型用户） | 输入门诊流程咨询问题，查看系统返回的流程指引 |
| 管理员 | 维护模拟知识库条目，查看匿名未命中问题记录 |

## 六、非功能性要求（课程设计层面）

- **易用性**：对话界面文字简洁，流程指引分条列出。
- **可维护性**：模拟知识库条目结构清晰，便于课程演示时增删改。
- **规范性**：需求描述与 UML 图纸术语一致，通过团队内部交叉检查。

## 七、本次已识别核心需求的交叉检查结论

本说明书仅覆盖上述四项核心功能与课程演示所需业务流程。六张 UML 图围绕这四项功能建模，完成本次已识别核心需求的交叉检查；未列入的功能留待后续版本讨论。
