## 1. 项目背景与商业论证（Business Case）

门诊导诊台日常承担大量**重复性、流程性**咨询：科室位置与就诊流程、挂号流程、就诊材料、检查须知等。这类问题有相对固定的答案、被反复提问，既占用导诊人力，也不同程度存在"不同人员答复口径不完全一致"的问题。

本项目针对上述流程性咨询，设计一套**基于模拟知识库的文本问答原型方案**。其基本逻辑是：门诊咨询用户提交**一个独立文本问题** → 问题通过校验后进入模拟知识库匹配 → **命中**则返回该条目中预先整理的**标准答复** → **未命中**则给出线下咨询指引，并将该问题**匿名**记录为待审核问题，供管理员后续补充知识。管理员依据预先准备的模拟业务资料人工整理标准答复、新增或修改条目，**审核后启用**。

**边界声明（项目名称"智能应答"极易被误读，特此逐条澄清）**：

1. "智能应答"**不表示已接入大模型**，也不表示系统具备任何诊疗、处方或分诊判断能力；
2. "对话"指**单轮文本问答**，不包含多轮上下文理解；
3. 本项目是**课程设计阶段的方案型项目**，交付物为设计文档，**不是可运行系统**；不接入真实医院信息系统（HIS），不处理真实患者数据；
4. 预期收益（减轻导诊重复负担、提升答复口径一致性）属于**业务愿景**。本阶段**没有实测数据**，不将其列为已达成结果，也**不虚构**响应时间、准确率或用户满意度指标。

## 2. 项目工作说明书（SOW）/ 产品范围描述

**产品定义**：一套面向"门诊流程咨询 + 模拟知识库维护"的**设计方案交付包**，由六类成果组成：

| 序号 | 成果类别 | 说明 |
| :-: | --- | --- |
| 1 | 需求与范围 | 项目目标与范围说明、需求范围追踪矩阵 |
| 2 | 业务模型 | 业务用例图与业务用例说明；两个重点场景的用例说明与活动流程图 |
| 3 | 结构模型 | 域模型（领域模型）与说明、类图、两张重点场景时序图（含 PlantUML 源文件） |
| 4 | 管理知识域 | 七项知识域模型（整合/范围/进度/质量/资源/沟通/风险）与三类预期目标 |
| 5 | 工程管控 | WBS 与 WBS 词典、初步进度计划、风险登记册 |
| 6 | 整合文档 | 项目章程、初步项目管理计划、成员性格（迈尔斯心理模型/MBTI）与岗位匹配、汇报材料 |

**明确不生产**：源代码、可运行原型、真实接口对接、部署运维方案。
