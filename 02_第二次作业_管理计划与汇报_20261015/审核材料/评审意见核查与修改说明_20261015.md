## 一、⚠️ 预警 1：关键路径与"总浮动 1 天、利用率 61%"的计算核验

### 1.1 复算结论：**算术自洽，但口径需要修正**

**（A）表内算术完全自洽 —— 三项数字全部复算通过**

对《项目管理计划_初步版》§3.5 的 13 项活动逐行复算（脚本重算，非目测）：

| 校验项 | 结果 |
| :--- | :--- |
| `EF = ES + 工期` | 13/13 通过 |
| `LF = LS + 工期` | 13/13 通过 |
| `总浮动 = LS − ES = LF − EF` | 13/13 通过（两法一致） |
| 活动工期之和 | **27 天** ✓ |
| 项目总工期（2026-09-01 → 10-15） | **44 天** ✓ |
| 工期利用率 = 27 / 44 | **61.4% ≈ 61%** ✓ |
| 最小总浮动 | **1 天**（A-1.3）✓ |

→ **评审意见中"请务必重新核验"的三项数字，复算后与文件一致，不存在算错。** 这一点可以放心。

**（B）但存在一处**口径缺陷**，评审的直觉是对的**

我**不采用 §3.5 表内的 ES 值**，而是**从依赖网络独立正推**，结果与表内不同：

| 算法 | A-1.3（汇报 PPT 全案集成）的总浮动 |
| :--- | :--- |
| ① 按依赖网络正推：A-1.1 最早完工 10-12 → A-1.3 最早 10-12 起、10-13 完工；后向自 10-15 逆推 LS=10-14 | **2 天** |
| ② 按甘特图实际排定日（A-1.3 起于 10-13） | **1 天** |

**根因**：§3.5 的 ES 直接取自甘特图条形的实际排定坐标，而**不是**依赖网络推得的最早开始日。两者相差 1 天（网络最早 10-12 vs 实际排定 10-13），于是"总浮动 1 天"其实是 *（交付日 − 排定日）*，**并非**网络意义上的真实松弛——真实的网络松弛是 **2 天**。

**（C）由此产生的逻辑张力（评审所指）**
- 若说"总浮动仅 1 天"，却又说里程碑采用"完成/未完成"二值判据，二者并置会让人误以为"几乎没有容错"。
- 更严谨的表述是：**该关键链浮动极小，各节点高度依赖、几乎无缓冲，须严格死守里程碑。**
