### 2.3 范围不蔓延（Scope Creep）防线

1. 不把"科室咨询/挂号咨询/医保咨询/检查须知"拆成独立用例，统一为"提交门诊咨询问题"的**咨询主题**；
2. 不因引入"匿名未命中记录"而顺带引入账号、会话、分类、权限等对象；
3. 分类、状态等**若需新增，先改范围说明与追踪矩阵**，再改模型与图纸——顺序不可颠倒。

## 7. 风险管理计划

### 7.1 方法与阈值

风险登记册采用 **P（概率）× I（影响）** 打分（1–5 分制）；约定阈值为：**P×I ≥ 14 → 高**、**9–12 → 中**、**≤ 8 → 低**。风险册须含字段：描述 / 概率 / 影响 / 等级 / 责任人 / 应对措施 / 触发条件；应对策略按规避 / 减轻 / 转移 / 接受分类。

### 7.2 风险接力（组长裁定）

> **裁定 6**：何亭玉《项目知识域模型与预期目标》§3.7 明写"供钱智超纳入正式风险登记册"的 **8 条风险，全部纳入《风险登记册》**，按 RSK 编号续编，并保留原负责人与协作人。钱智超原 6 条（RSK-201~206）与何亭玉 8 条合并为**统一台账**，两处不得互相矛盾。
>
> 8 条为：范围膨胀、UML 术语或流程冲突、成员交付延期、未命中兜底不完整、知识过期或未经审核启用、医疗咨询越界、模拟文本含真实个人信息、整合版本或格式不一致。

### 7.3 风险闭环判据

风险关闭的判据是**对应缺陷已修订且检查通过**；**不能仅以"已经提醒"作为解决证明**。风险册的"闭环率"须写**数值**（如 `4/14 = 29%`），不得写"动态监控中"。

## 8. 变更控制（整合管理）

### 8.1 变更控制委员会（CCB）

课程项目规模下，CCB 由**组长（主席）+ 受影响文件负责人 + 一位交叉检查人**组成，由组长最终裁决。

### 8.2 变更流程

| 步骤 | 内容 |
| :-: | --- |
| 1 | **提出**：任何成员发现需变更的范围/术语/坐标，向组长说明原因、影响范围与建议处理方式 |
| 2 | **评估**：组长判断是否触及范围基线；触及者必须先改《项目目标与范围说明》与《需求范围追踪矩阵》 |
| 3 | **裁定**：组长书面裁定并群公告 |
| 4 | **同步**：受影响文件负责人按裁定统一修改；跨图项由组长指定交叉复核 |
| 5 | **复核**：组长在冻结前做一次一致性扫描，确认所有受影响文件已同步 |

### 8.3 变更控制红线

- **范围基线未更新前，不得在模型/图纸中静默扩展**；
- **内容冻结（10-13 22:00）之后**，仅接受"错别字与格式"类修改，内容变更一律走 QC 记录留痕（本批次以附录形式注明）。
- 提交包内**不得残留**任何未经裁定的双份口径（如"标准答案/标准答复"并存、"已解决/已处理"并存）。

## 9. 统一口径与术语基线（组长裁定，2026-10-12 生效）

> 本系裁定针对全组跨文件一致性存在的 **7 项冲突**，由组长统一发布，全组在内容冻结前同步。裁定一经发布即为唯一口径，本计划与《项目章程》保持一致。

### 裁定 1 ｜ 知识条目字段 = **8 字段**，用词统一 **"标准答复"**

| 序 | 字段 | 说明 |
| :-: | --- | --- |
| 1 | 知识编号 | 唯一；新增编号唯一，编辑保持编号不变 |
| 2 | 标准问题 | 条目对应的规范化问题 |
| 3 | 关键词 | 用于匹配 |
| 4 | **标准答复** | 命中时返回的内容（原"标准答案"一律改写） |
| 5 | 来源说明 | 答复依据 |
| 6 | 最近更新时间 | 内容时效 |
| 7 | 维护人 | 更新责任 |
| 8 | 启用状态 | 是否可用于匹配（审核后启用） |

- 澄清："标准答复"**既是条目的字段名，也是命中时返回的值对象名，二者为同一份数据**，不重复维护（王宇坤《领域模型说明》§4.3 已说明）；
- 受影响文件（**6 份**）：蒋诗韵《项目目标与范围说明》D-06、《业务用例说明》§8、《需求范围追踪矩阵》AC-05/06/07；王宇坤《领域模型说明》§4.2；张天乐《关键问题分析与技术路线》§四；何亭玉《项目知识域模型与预期目标》§3.4/§3.6/§四。

### 裁定 2 ｜ 状态词统一为 **三态：待审核 / 已处理 / 不纳入**

- **停用**"已解决""已补充"等异名；
- 语义：问题初始为**待审核**；纳入并启用条目后记为**已处理**；决定拒绝纳入时记为**不纳入**；
- **保留状态**的理由：场景二"审核后才可启用"在无状态下无法讲通；
- 配套要求：因王宇坤声明"匿名未命中记录当前不设状态，若增加须同步修改范围说明与追踪矩阵"，故**蒋诗韵须在《项目目标与范围说明》与《需求范围追踪矩阵》补入状态定义**；王宇坤同步更新《领域模型说明》与 PlantUML 注释。

## 10. 配置管理与版本控制

1. **目录规范**：文字文档→`docs/`；图纸→`diagrams/`；PlantUML 源→`diagrams/source/`；禁止 `docs/docs/`、`diagrams/diagrams/` 冗余层级。
2. **命名规范**：图名与正文引用逐字一致；文件不带 `(1)`、`_最终_最终` 等后缀。
3. **版本留痕**：提交前保留一份 `_backup/` 于各人本地，不进入提交包；提交包内一律为定稿。
4. **提交包卫生**：工作产物（图片修改清单、`_backup_*`、临时脚本）**不进入提交包**。
5. **源文件要求**：凡交付 `.png`，必须在 `diagrams/source/` 同时交付可重导出源（`.puml`），以应对排版的临时微调（对应 RSK-206）。
