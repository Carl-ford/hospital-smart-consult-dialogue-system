# 项目初步计划

## 一、规划原则

本项目采用**滚动式规划（Rolling Wave Planning）**：近期工作细化到可验收结果，远期工作只做粗粒度安排，待阶段成果出来后再细化下一段。

- 9月（本次作业阶段）详细规划；
- 10月及以后仅保留方向性安排；
- 不做超出当前课程阶段的详细任务分解。

## 二、阶段与里程碑（仅细化9月）

| 阶段 | 时间 | 可验收结果 |
|------|------|------------|
| 设计基线 | 9月14日–9月16日 | 需求说明书定稿；项目边界与范围明确；初步计划通过组长审核 |
| 建模与文档 | 9月16日–9月17日 | 六张 UML 图初稿；十大知识域文档、预期目标文档、4-Frame 文档初稿；三张项目管理图初稿 |
| 交叉检查 | 9月18日 12:00 前 | 全部素材交付主笔；UML 图之间术语与逻辑完成团队内部交叉检查 |
| 报告整合 | 9月18日–9月19日 | 结题报告初稿；格式、引用、图文一致性核对完成 |
| 课程交付 | 9月20日 | 终稿提交，全部文件按仓库目录归档 |

> 注：10月以后的原型开发、测试安排，待本次设计基线交付后再行细化。

## 三、假设与约束

- **团队规模**：8 人（1 名组长 + 7 名组员），按文档分工并行推进。
- **固定截止日期**：9月20日为课程作业提交时间，后续阶段按课程安排推进。
- **可用工时**：课程项目以课余时间为主，各组在截止日期前自行安排进度。
- **技术约束**：仅做需求设计与 UML 建模，不进行代码开发。
- **数据约束**：使用模拟知识库与模拟患者问题，不接入真实医院接口，不处理真实患者数据。
- **范围约束**：严格按本仓库 README 所列作业范围执行，不额外扩展功能。

## 四、计划更新机制

- **设计基线完成后**：再细化后续原型开发阶段的任务安排与分工。
- **原型阶段完成后**：再细化测试用例与交付安排。
- 每个阶段结束时，组长组织一次简短复盘，更新本初步计划中粗粒度部分。
